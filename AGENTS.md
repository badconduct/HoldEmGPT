# Project scope

- The Dockernet web application is the active product and development target.
- Implement, test and deploy web changes through the existing GitHub/Dockernet
  review workflow. Follow the infrastructure repository's deployment runbook.
- Do not start a separate local listening/demo server or present a local game
  as the delivered website update. Disposable automated test servers are fine.
- The C project is a basic demo, not production. Native conversion follows the
  finished web product. Do not port features or modify the C demo unless the
  user explicitly requests native work again.
